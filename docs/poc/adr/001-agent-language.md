# ADR-001：节点 Agent 实现语言（设计 §5.5 / add-poc-decision-gate §5.1）

- **状态**：提议（POC 决策门评审中）
- **日期**：2026-10-28
- **决策人**：平台团队

## 背景

设计 §5.5 要求 POC 阶段用 Rust vs Go 原型对比（内存、CPU、解析稳定性、团队能力），输出语言决策记录。
节点 Agent 职责：磁盘发现、SMART 预检、LVM executor（唯一 PV/VG/pool 写路径）、exporter 指标采集。

## 候选

| 维度 | Rust | Go |
| --- | --- | --- |
| 内存/CPU | 无 GC、零成本抽象，常驻 DaemonSet 内存更稳 | GC 停顿可控，资源占用略高但可接受 |
| 解析稳定性 | 强类型 + 模式匹配，外部命令 JSON 解析更安全 | 标准库 JSON 易用，生态成熟 |
| 命令执行安全 | 原生 argv 数组，无 shell 拼接习惯 | 同左，依赖编码规范 |
| 团队能力 | 需评估团队 Rust 熟练度 | 控制面已用 Go，团队 Go 熟练 |
| 运维/构建 | 交叉编译、镜像体积可控 | 交叉编译简单、镜像体积可控 |

## 决策

**采用 Rust 作为节点 Agent 默认语言**（设计默认即 Rust），依据：
1. Agent 是常驻、贴近宿主机的特权进程，内存确定性与无 GC 停顿更利于稳定性；
2. 强类型与模式匹配降低对宿主机命令输出解析的脆弱性；
3. exporter 与 agent 同二进制 `--mode` 切换，单一语言降低维护面。

**前提/风险**：若团队 Rust 熟练度不足导致交付风险，可回退 Go（控制面同栈）。
须在 POC 阶段用原型实测内存/CPU 与解析稳定性后，于决策门评审确认。

## 影响

- `agent/` 模块以 Rust 实现（已启动，见仓库 `agent/`）。
- 构建流水线需 Rust 工具链；镜像多阶段构建。
- 与控制面 Go 通过 CRD/Status 契约通信，语言异构不影响集成。
