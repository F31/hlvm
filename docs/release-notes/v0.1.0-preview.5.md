# hlvm v0.1.0-preview.5

**定位：技术预览版（Developer Preview）。用于集成联调、方案评估与内部汇报，禁止用于生产环境。**

第五个技术预览版，主题是**给三方对账补上可观测性**。preview.4 把 lvs 一侧接上了数据，
但失败关闭的代价没有被观测：上报过期时控制器只打一条 `Info` 日志就整轮放弃对账，
Agent 长挂期间平台看起来一切正常。本版把这条链路补成「指标 + 告警规则 + 守卫测试」。

本版**不含 agent 功能变更**（agent 仍可运行 preview.4 镜像）。

## 1. 本版解决了什么

| 问题 | 本版处理 |
|---|---|
| 放弃对账只留 Info 日志，无指标无告警 | 新增 `storage_controller_drift_reconcile_skipped_total{reason}`，reason 为闭集常量 |
| Agent 停止上报后不再有 reconcile 触发，滞后秒数会冻结在挂掉前瞬间 | 改为暴露**上报时间戳** `storage_controller_lv_report_timestamp_seconds`，配合 `time() - ts` 判停摆 |
| 「从未上报」与「上报陈旧」不可区分 | 单独暴露 `storage_controller_lv_report_present`（`present=0` 时不存在时间戳序列，Stalled 对它恒为 no data） |
| 漂移只存在于 TTL 过期的事件里，无法做常驻告警 | 新增 `storage_controller_drift_items{kind}` |
| 空集群（无 PVC）时一次 reporter 调用都不发生，Agent 挂掉完全不可观测 | 新鲜度指标改为覆盖**全部 NodeVG**（直接读 `NodeVG.status`），不跟随对账路径 |
| 告警规则引用拼错的指标名会导致「永不触发」的假绿 | `TestAlertRulesReferenceKnownMetrics` 从 collector `Describe` 取真实 fqName 校验 |

三个容易写错、且写错就会产生假绿的语义，本版显式钉死（并做了变异校验）：

- **全量替换**：NodeVG 删除后必须 `DeleteLabelValues`，否则旧时间戳永冻，
  `time() - ts` 持续增长 → 永久误告警。
- **跳过轮次不清零漂移条目**：否则 Agent 抖动一次就把「有漂移」改写成 0，伪装成已恢复。
- **消失的 kind 置 0 而非删序列**：序列消失会让 `drift_items{kind=...} > 0` 变成 no data，
  被告警系统当成恢复。

## 2. 不适用场景（请先读这一节）

- 承载任何生产或准生产数据；
- 依赖平台**自动修复** LVM 漂移（设计明令 SHALL NOT 自动修复，只发事件 + 建议）；
- 依赖「空集群里手工 `lvcreate` 也会被告警」：`DetectDrift` 的「任一侧为空即返回」契约
  未改，**没有 PV 时检不出人工 LV**；
- 依赖本版指标在**多副本**下可直接聚合：指标只在 leader 副本上更新
  （controller-runtime leader election），Prometheus 需抓全部 Pod 或抓 leader；
- 认为「有告警规则 = 已被求值」：仓库内只有规则清单与静态守卫测试，
  **未接真实 Prometheus 做规则求值**。

## 4. 升级注意

1. **只需升级控制器**：`kubectl -n hlvm-system set image deploy/hlvm-storage-controller \
   manager=ghcr.io/f31/hlvm/storage-controller:v0.1.0-preview.5`。
   本版 agent 无功能变更，可继续运行 preview.4（版本号偏差已知、不影响行为）。
2. **不要 apply 仓库的 CRD bases**：真机 `nodevgs.status` 是
   `x-kubernetes-preserve-unknown-fields: true`，而仓库 `config/crd/bases` 是 `status: {}`，
   apply 会把 agent 写入的 `logicalVolumes` / `lastLVReportTime` 静默 prune 掉。
3. **告警规则按需 apply**：`config/prometheus/alert-rules-drift.yaml` 依赖
   Prometheus Operator CRD（`PrometheusRule`）；未装 Operator 时 apply 会报 no matches。
4. 若节点上曾有手工 `ctr images pull` 卡住，镜像已在节点却 Pod 一直 `ContainerCreating`：
   先杀掉手工进程（与 kubelet 争 content store 锁）。

## 5. 验收（已执行，2026-11-12）

控制器升级到 `v0.1.0-preview.5` 后，用 `docs/poc/scripts/drift-metrics-verify.sh`
在真机执行：**PASS=13 / FAIL=0 / SKIP=0**（rc=0），只读复跑 **PASS=4 / SKIP=1**。
环境：leader `c76fdf4f7-9xmx4`，agent 仍 `.preview.4`（本版无 agent 变更）。

| 判据 | 证据 |
| --- | --- |
| 两节点新鲜度 | age 32s / 31s，`present=1` |
| 停摆可观测 | 时间戳冻结、age 自然增长到 203s（> 180s），未伪造 status |
| 放弃对账被计数 | `skipped_total{reason="report_stale"}` 0 → 5 |
| 不给假告警 | 停摆期间 `StorageDrift` 事件 3 → 3 |
| 恢复 | 移除 taint 后 Pod 重建，age=0s |

执行方式与两处**判据自身**缺陷的修正（`DaemonSet` 无 `spec.replicas`；Prometheus 对
大数用科学计数法）见 ADR-006 §17.6。注意：无 PV 时控制面不调用 reporter，
`report_stale` 分支需 fixture PV 才可达，脚本内已实现并在恢复上报前删除。
