# hlvm v0.1.0-preview.1

**定位：技术预览版（Developer Preview）。用于集成联调、方案评估与内部汇报，禁止用于生产环境。**

首个可部署形态：自研本地存储平台的**控制面（Go）** + **节点 Agent（Rust）**。这一版要回答的问题不是
「能不能上生产」，而是「骨架对不对、接口稳不稳、往哪个方向补验证」。因此所有能力都在 kind 1.36 上端到端
跑通并可复现，但**全部真实硬件路径尚未验证**（见 §4）。

## 1. 不适用场景（请先读这一节）

以下用途本版本**明确不支持**，请不要尝试并据此评估产品：

- 承载任何生产或准生产数据；
- 在真实 LV / thinpool 硬件上做容量与故障演练，并引用其结果做决策；
- 作为灾备方案的一部分（备份恢复闭环未验证）；
- 灰度放量与上线评审的依据。

## 2. 本版本包含

| 层 | 能力 |
|---|---|
| CRD | `NodeDisk`(v1beta1 存储) / `NodeVG` / `StorageTask` / `StorageNodeOps` / `ThinPoolPolicy` |
| 控制面 | 磁盘/VG 对账、纳管状态机、Stale 条件、删盘保护、孤儿 GC、容量治理（Locked + 节点标签 + 滞回解锁）、NotReady 自动 isolate |
| 多版本 | NodeDisk dual-version + conversion webhook；storedVersions 切换/回滚演练；serving 证书轮换 |
| 准入 | VAP 静态层 + mutating webhook 动态层；PVC 校验、删除保护、locked 节点调度排除 |
| 节点侧 | 单二进制 4 模式（agent/exporter/device-plugin/doctor）；磁盘发现、SMART、预检、LVM 写路径（唯一写者）、device plugin `hlvm.io/disk`、kubelet 重启自愈 |
| 可观测 | Prometheus 指标 + 告警评估 + 只读大盘 + 纳管入口 |
| 交付 | 集成脚手架 23 相位（kind，约 120 条断言）；真实集群部署脚本 `scripts/real-cluster/`；4 个容器镜像 |

## 3. 验证到什么程度

| 验证面 | 环境 | 结果 |
|---|---|---|
| Go 单元测试 | `go test ./...`（GOWORK=off） | 165 个 `Test` 全绿 |
| 控制面 e2e | envtest 1.36.2（真实 kube-apiserver + etcd） | 全绿 |
| Rust 单元测试 | `cargo test --all-targets` | 142 个用例全绿 |
| 集成端到端 | WSL2 kind 1.36.1，3 节点（1 CP + 2 worker） | 23 相位、约 120 条断言、0 FAIL |
| CI | GitHub Actions | Go / Rust / 4 镜像 / Ready 全绿 |

集成断言的判据是**退出码 0 + 无 `FAIL:` / `[error]` + 每个相位打出收尾 PASS 汇总行**；条数会因环境分支
（SKIP 与否）浮动，不要把不同时间的条数相减当作回归判据。

## 4. 未验证清单（本版本最大的风险）

| # | 项 | 为什么没验 | 影响 |
|---|---|---|---|
| 1 | 真实 LV / thinpool 行为 | 本地无块设备与 LVM 栈，kind 用 loop 设备模拟 | 容量治理、dmeventd 自动扩容、打满演练、告警延迟全部未实测 |
| 2 | `/dev/disk/by-id`（udev） | kind 节点无 udev，只有 `dev-<name>` 回退分支 | 真机设备 ID 形态可能不同，纳管与 device plugin 的匹配路径未验证 |
| 3 | Velero 备份恢复闭环 | 本地无法拉取所需镜像，相位 SKIP | RTO/RPO 无数；pre/post hook 与快照一致性未验证 |
| 4 | 节点扩缩容与重平衡 | kind 静态拓扑 | 跨节点调度拓扑只覆盖「容量耗尽/Pending/回调度」，真实增减节点未验 |
| 5 | 灰度与上线评审 | 需真实环境与评审流程 | hardening 5.2/5.3、poc V.1-b 全空 |
| 6 | 多 apiserver 副本下的 conversion | 单 CP | webhook 高可用与证书在多副本下的行为未验 |

## 5. 已知限制

- **4 个 Kind 仍为 v1alpha1**（`NodeVG` / `StorageTask` / `StorageNodeOps` / `ThinPoolPolicy`），
  尚未版本化；`NodeDisk` 已是 v1beta1 storage。
- **控制面与 Agent 的 K8s 客户端小版本不一致**：Go 侧 client-go 1.33，Rust 侧 k8s-openapi 1.36。
  编译互不影响，但跨版本行为差异未系统验证。
- **webhook 故障域**：切到 v1beta1 存储后，v1alpha1 读写会经过 conversion webhook；
  该组件故障时 v1alpha1 不可用（v1beta1 可读）。请勿在此版本上依赖 webhook 的高可用。
- GHCR 包为私有，集群侧需注入 `imagePullSecret`（见 runbook §6）。

## 6. 获取与部署

镜像（请使用显式版本标签，不要引用 `:latest`）：

```
ghcr.io/f31/hlvm/storage-controller:v0.1.0-preview.1
ghcr.io/f31/hlvm/storage-webhook:v0.1.0-preview.1
ghcr.io/f31/hlvm/crd-conversion:v0.1.0-preview.1
ghcr.io/f31/hlvm/storage-agent:v0.1.0-preview.1
```

- 本地 kind 复现：`scripts/m15-integration.sh all`（WSL 入口 `scripts/m15-wsl.sh`），
  步骤与排障见 `docs/m15-integration-runbook.md`。
- 真实集群：`scripts/real-cluster/README.md`（3 台起步，1 CP + 2 worker，K8s ≥ 1.36）。
- 版本自检：`storage-controller --version` 应输出
  `v0.1.0-preview.1 (commit <sha>, built <ts>)`；`hlvm-agent --version` 输出 Cargo 版本。
