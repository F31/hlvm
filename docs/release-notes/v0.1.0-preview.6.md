# hlvm v0.1.0-preview.6

**定位：技术预览版（Developer Preview）。用于集成联调、方案评估与内部汇报，禁止用于生产环境。**

第六个技术预览版，主题是**把 preview.5 之后累积的配置、判据与记账固化成一个可复现的版本**。
本版**不含 Go / Rust 产品源码变更**：preview.5 之后的 11 个 commit 只改部署清单、
集成判据脚本、告警配置、守卫测试与文档。相对 preview.5，二进制行为等价，差别只在
版本串与随版固化的配置。

本版同时收口了一次严重的记账偏差：真机 `m15 all` 已 16 个 verify 相位零 FAIL、
对账有效域 D 已从 2 扩到 3，但 ADR / runbook / CHANGELOG 里仍写着「未跑 `m15 all`」
「CP 未扩」「M15 至今没有部署 TopoLVM CSI」。**代码全绿而记账落后**，会让下一个人
照着过期的诚实边界决定「哪些还没验」；本版把这些结论回填，历史快照一律加注更正、
不改写。

## 1. 本版解决了什么

| 问题 | 本版处理 |
|---|---|
| 对账有效域 D 只有 2 个 worker，CP 不产生 PV | 新增 CP `10-60-131-187` 的 NodeVG seed，三 DS 加 control-plane 容忍，逐节点 PVC→LV→写入→回收 E2E 全 PASS，**D=3** |
| CP 上消费 Pod 因 taint 无法调度，E2E 假红 | `pvc-supply-e2e.sh` 增 `TOLERATE_CONTROL_PLANE=1` |
| 双版本 CRD 停在中断态，bootstrap 守卫拦下 `m15 all` | 确认 `storedVersions` 已干净后执行 `restore_single_version_crds`，5 CRD 收回单 `v1beta1`，4 个真实对象无损 |
| `verify-lvmd` 在扩域后两条断言假红 | 测试 NodeVG 隔离到 `m15-lvmd-fake-node`，避开与 CP 上真实生产 NodeVG 的聚合 |
| `verify-cert-rotation` 连续假红、一次卡死 2h+ | 探针端口改 `19499`（避开 hnb 占死的 `19443`）、转发 svc 的 443、Pod→Service、`pf_rebuilds` 落盘 |
| 告警只有规则文件，没有落点 | 新增 Alertmanager 路由/抑制 + Grafana 面板 + 离线/实例两级校验（§20–§21） |
| 告警规则「只有清单、从未被求值」 | promtool 真实求值覆盖全部 22 条告警 + 4 条记录规则（§18–§19） |
| 真机 GHCR 直连 ~27KB/s、扩容与 all 前置不稳 | `registry-mirror.sh` 固化镜像源；drift E2E 容忍控制面 |
| 记账落后于真机现实 | ADR-006 §22；runbook §4 §B 逐项状态表、§6 / §10.7 / §10.19 更正、§10.20 复跑要点；CHANGELOG 追加 |

## 2. 不适用场景（请先读这一节）

- 承载任何生产或准生产数据；
- 依赖**端到端备份/恢复与 RTO/RPO**：真机拉不到 `docker.io/velero`、`docker.io/minio`，
  `verify-velero` 为 SKIP，闭环未验证；
- 依赖**告警整链**：无常驻真实 Prometheus / Alertmanager / Grafana。规则求值是离线
  promtool，抑制是临时容器实例，「规则触发 → 路由 → 抑制 → 投递」整链未端到端验证；
  接收器地址仍是形状示例，**部署时必须替换**；
- 依赖平台**自动修复** LVM 漂移（设计明令 SHALL NOT 自动修复，只发事件 + 建议）；
- 依赖「空集群里手工 `lvcreate` 也会被告警」：`DetectDrift` 的「任一侧为空即返回」契约
  未改，**没有 PV 时检不出人工 LV**；
- 依赖本版指标在**多副本**下可直接聚合：指标只在 leader 副本上更新；
- 认为 `m15 all` 零 FAIL 等于 §B 19 项递延已验收 —— **不是**，见第 6 节。

## 4. 升级注意

1. **真机仍运行 `:v0.1.0-preview.5`**。若要把版本串与本 tag 对齐，需显式
   `kubectl -n hlvm-system set image` 四个组件并重新部署常驻 agent DS；本版没有
   在新的 `:v0.1.0-preview.6` 镜像上重跑 `m15 all`（见第 5 节）。
2. **不要 apply 仓库的 CRD bases**：真机 `nodevgs.status` 是
   `x-kubernetes-preserve-unknown-fields: true`，而仓库 `config/crd/bases` 是
   `status: {}`，apply 会把 agent 写入的 `logicalVolumes` / `lastLVReportTime`
   静默 prune 掉。
3. **`verify-cert-rotation` 的本地探针端口固定 `19499`**。`19443` 被 `hnb-system`
   的 `svc/tunnel-server` 常驻 port-forward 占用，改回去必然
   `bind: address already in use`；转发目标须用 `svc/hlvm-crd-conversion` 的 443
   （svc 无 9444 port），且不能用具体 Pod 名。复跑前详见 runbook §10.20。
4. **Alertmanager 接收器是形状示例**（`hlvm-alert-sink...`），本仓库不含适配器实现，
   部署前必须替换并验证投递；`config/alertmanager/alertmanager.yaml` 依赖
   Prometheus Operator CRD 的告警规则按需 apply。
5. 生产/集成一律引用 `:vX.Y.Z`。`:latest` 会被下一次 main push 覆盖，
   用 `:latest` 跑出的结论无法复现。

|---|---|---|

| `verify-cert-rotation` | 16 条证书链断言 + 4 条多 Kind conversion smoke 全 PASS，`TLS 探针无响应` 0 次 | 同上 |

| 常驻 agent DS 恢复 | 153 / 166 / 187(CP) 各 `PASS=17 / FAIL=0` + `REAL_WRITE_OK`（宿主 VG 真实 lvcreate/lvs/lvremove） | ADR-006 §22.6 |
| 上一次提交 CI | run 131（`20c3783`）：Go / Rust / Observability configs / Container images / **Ready** 全 success | GitHub Actions |
| 本版本地验证 | `go build ./...` / `go vet ./...` / `go test ./...`、`cargo test --all-targets`、`bash -n`、`git diff --check` | 发版前执行 |

**诚实边界**：本版发布前**未重跑 `m15 all`**。依据是本轮零产品源码变更、判据脚本与
集群状态未变、第五遍全绿刚于 2026-11-12 完成；但「未在新 tag 上重跑」本身是事实，
不因行为等价而抹去。`all` 分支 for 循环后无汇总行是脚本设计，日志停在
`verify-velero` 不是异常。

Release 正文是 tag 时刻的快照，事后不回写；后续真机若有新结果，记入 ADR / CHANGELOG
与下一版发布说明。

## 6. 仍未闭合

- **三个 SKIP（不计 PASS）**：`verify-velero`（docker.io 镜像不可达，端到端备份/恢复与
  RTO/RPO 未验）、`verify-device-hotplug`（无 `M15_DISK_ATTACH_CMD`）、
  `verify-kubelet-restart` 两条 checkpoint 断言（本环境 kubelet 不落盘
  `PodDeviceEntries`）。
- **§B 19 项递延仍未逐项验收**（runbook §4 状态表）：告警延迟演练（Critical≤1min /
  Warning≤5min）、指标口径与 `vgs`/`lvs` 对账、dmeventd autoextend ≤30s、
  thinpool 打满（`CapacityStatus=Locked` / 准入拒绝 / 告警链路）、灰度滚动重载、
  Velero 闭环、fio 实测与评审 / 上线门禁。`M14-closure.md` 风险 #3
  「**不能视为 production-ready**」结论不变。
- **可观测性**：无常驻真实 Prometheus / Alertmanager / Grafana；`equal` 标签在真实
  exporter 序列上是否存在未验；投递、模板渲染、`repeat_interval` 手感未测。
- **链路与语义**：A 链路设备插件仍只在 153 单节点；`freeBytes` 是 VG 物理 free
  （约 2 GiB）≠ CSI 的 thin-pool 36 Gi；NodeVG 仍手工 seed；聚合 ConfigMap 由脚本
  同步而非控制器渲染；指标只在 leader 副本。
- **平台集成**：hnb 联合验收仍停在接口级（`HTTP 200 /version`），`hnbctl cluster import`
  缺 HTTPS `--platform-url`、bearer token、kubeconfig credential、agent enrollment。
- **已登记风险**：Go / Rust k8s 依赖代差（`k8s.io/api 0.33.0` vs `client-go 0.32.1` /
  `controller-runtime 0.20.4`），由 `deps_test.go` 锁基线，待真实集群回归稳定后单独立项；
  私有 GHCR 包路径的 `post-install.sh` 只 patch default SA（公开包模式不覆盖该路径）。
